# YOLO preprocessor for 3ds Max renders -> Stable Diffusion

Скрипт `preprocess_for_sd.py` автоматически делит объекты на 2 группы:

- **preserve** — объекты, где нужно сохранить геометрию/четкость форм.
- **rewrite** — объекты, которые можно сильно перерисовать в SD.

Это удобно для пайплайна с inpaint/img2img:

1. Рендер из 3ds Max.
2. YOLO-сегментация и генерация масок.
3. В SD используешь:
   - `sd_base.png` как базовое изображение,
   - `inpaint_mask.png` как маску областей для перерисовки.

## Установка

```bash
pip install ultralytics opencv-python numpy
```

## Подготовка политики классов

Сделай JSON файл по примеру `class_policy.example.json`:

```json
{
  "preserve": ["car", "person", "chair"],
  "rewrite": ["sky", "potted plant"]
}
```

Если класс не указан ни в одном списке, скрипт по умолчанию относит его к `rewrite`.

## Запуск

```bash
python preprocess_for_sd.py \
  --input ./renders \
  --output ./prepared \
  --policy ./class_policy.example.json \
  --model yolov8x-seg.pt \
  --conf 0.25 \
  --rewrite-blur 21
```

## Что генерируется

Для каждого входного файла создаётся папка `output/<имя_файла>/`:

- `preserve_mask.png` — белая маска объектов, которые нужно сохранить.
- `rewrite_mask.png` — белая маска объектов, которые можно перерисовать.
- `inpaint_mask.png` — копия `rewrite_mask.png` (удобно сразу в SD).
- `sd_base.png` — картинка с замыленными rewrite-областями, чтобы SD активнее их перерабатывал.
- `prompt_hints.txt` — список найденных классов и их категории.

## Практический совет

Для архитектурных/интерьерных рендеров обычно имеет смысл:

- `preserve`: мебель, техника, люди, транспорт, важные элементы сцены.
- `rewrite`: небо, растения, фоновые декоративные объекты, мелкие шумные детали.

Если объект важный, но YOLO его не ловит — попробуй:

- снизить `--conf` (например до `0.15`),
- взять более подходящую seg-модель,
- дообучить модель на своих классах.
